# AI sync

`ai/` is the single source for every AI tool's files. `sync.mjs` generates the tool-specific copies. It has no dependencies (Node >= 22) and is idempotent: a second run changes nothing.

```sh
yarn ai:sync                          # tools from .tempo.json "ai.tools"
yarn ai:sync --tools claude,cursor    # override
yarn ai:sync --check                  # exit 1 when generated files are out of date (no writes)
yarn test:ai-sync                     # node --test
```

| Tool      | Generated from                          | Output                                                                                       |
| --------- | --------------------------------------- | -------------------------------------------------------------------------------------------- |
| `claude`  | `ai/skills`, `ai/commands`, `ai/agents` | `.claude/skills/<name>/SKILL.md`, `.claude/commands/<name>.md`, `.claude/agents/<name>.md`   |
| `cursor`  | `ai/rules`, `.mcp.json`                 | `.cursor/rules/<rule>.mdc` (`description`, `globs`, `alwaysApply`), `.cursor/mcp.json`       |
| `copilot` | `AGENTS.md`, `ai/rules`                 | `.github/copilot-instructions.md`, `.github/instructions/<rule>.instructions.md` (`applyTo`) |

- Rule frontmatter: `description` and `globs` (comma separated). `architecture`, `naming` and `verification` are `alwaysApply: true` in Cursor. A rule without `globs` applies to `**` in Copilot.
- Every generated text file carries `<!-- generated by tempo ai sync from <source> — edit the source -->` after any frontmatter. `.cursor/mcp.json` is JSON and cannot carry it. `${VAR}` in `.mcp.json` becomes `${env:VAR}` for Cursor.
- Generated files that lost their source are removed; files without the header (hand-written ones such as `.claude/settings.json`) are never touched.
- The generated files are committed so a project works before the CLI is installed. Edit `ai/`, run `yarn ai:sync`, commit both.
- `tempo ai sync` (CLI) calls this script.
