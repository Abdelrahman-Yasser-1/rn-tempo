# i18n

No hard-coded user-facing strings. Every string is a key in both `en` and `ar`.

- Files: `src/locales/<lang>/<ns>.json`, one per namespace per language. Languages: `en` (default, fallback) and `ar` (RTL).
- Namespaces: `common`, `errors`, `validation`, `auth`, `home`, `profile`, `settings`, `items`, `app`, `forms`. A new feature adds its own namespace file in **both** languages.
- Key format: nested camelCase, e.g. `login.submitButton` in namespace `auth`.
- In code: the typed selector form, `t(($) => $.login.submitButton)` after `useTranslation('auth')`, or `t(($) => $.login.submitButton, { ns: 'auth' })`. Types come from `src/services/i18n/i18next.d.ts` (`CustomTypeOptions` with `resources` typeof `en` and `enableSelector: true`), so a missing or renamed key is a type error and go-to-definition works.
- **A string key in `t()` is a lint error** (`rn-tempo/restricted-syntax`), and so is a `Trans` `i18nKey` string. Never mix the two styles.
- **No dynamic keys.** A template-literal key such as ``t(`status.${s}`)`` is a lint error: it loses type safety and the extractor cannot see it. Map values to keys with an `as const` object built with `keyFromSelector`, e.g. `const STATUS_KEYS = { open: keyFromSelector(($) => $.status.open, { ns: 'items' }) } as const`, then `t(STATUS_KEYS[status], { ns: 'items' })`.
- **Keys that travel as data** (Zod messages, error and slide key maps) are built with `keyFromSelector(($) => $.email.required, { ns: 'validation' })` from `i18next`: typed, rename-safe and read by the extractor. The result is a `SelectorKey` that `t(key, { ns })` accepts. A key that arrives as plain text, such as `error.message` of a form field, goes through `toKey` from `@services/i18n/keys`, the only sanctioned cast. The shared `Text` takes a selector in `tx`, e.g. `tx={($) => $.sheet.close}` (common namespace).
- `en` and `ar` must have identical key sets. `yarn i18n:check` (`i18next-cli lint` and `extract --ci`) enforces it; the lint checks are errors.
- Lint: `i18next/no-literal-string` (mode `jsx-only`, error) flags literal text in JSX of `src/**/*.tsx`. Tests and stories are exempt. Excluded JSX attributes: `className styleName style type key id width height testID accessibilityRole name variant`. Accessibility labels and placeholders must use keys.
- The shared `Text` accepts a `tx` selector plus `txOptions` instead of children.
- Validation messages (Zod) are i18n keys in the `validation` namespace, built with `keyFromSelector`.
- **Plurals:** pass `count` and write one key per CLDR form. English needs `_one` and `_other`. Arabic needs all six: `_zero`, `_one`, `_two`, `_few`, `_many` and `_other`. `yarn i18n:check` (`extract --ci`) fails when a form is missing in a language. Example: `items:list.count`, `t(($) => $.list.count, { count })`. Write the number as `{{count, number}}`.
- **Context** (gender or role variants): name the variants `<key>_male` / `<key>_female` (or `_admin` / `_user`) and pass `t(($) => $.greeting, { context })`. Keep the base key as the fallback for any other value. Context variants are kept by `extract.preserveContextVariants`, because the context is computed at runtime. Example: the Home greeting (`greeting_male`, `greeting_female`).
- **Formatting inside a sentence** uses the built-in Intl formatters of i18next: `{{amount, currency(USD)}}`, `{{n, number}}`, `{{date, datetime(dateStyle: medium)}}`, so numbers, money and dates follow the active language. Pass the raw number or `Date` as the option. Register an app formatter with `i18n.services.formatter.add` in `services/i18n` only when a built-in cannot do it. `@shared/utils/format` stays for values that are not part of a sentence (a price on its own line, a list cell).
- **Missing keys are loud in development:** in `__DEV__`, a missing key logs a warning (language, namespace, key; never values) through the logger. Release builds are unchanged. `debug` follows `LOG_LEVEL=debug` and stays off under Jest.
- The language is stored in MMKV `app.language`. First launch: device locale if supported, else `en`.
- Switching LTR/RTL: `I18nManager.allowRTL(true)` + `forceRTL(isRTL)`, then `RNRestart.restart()`, after a confirmation dialog. Use `changeLanguage` from the language manager, never call these directly.
- Format dates, numbers and currency with the `Intl`-based helpers in `@shared/utils` outside sentences, and with the message formatters inside sentences, never by manual string building.

```tsx
// ✅
const { t } = useTranslation('auth');
<Text>{t(($) => $.login.submitButton)}</Text>;

// ❌ string key, literal in JSX, key in only one language
t('login.submitButton');
<Text>Sign in</Text>;
```
