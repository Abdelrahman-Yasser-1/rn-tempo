Every project has three environments. The values below are read from `template/.tempo.json` when the docs are built, so they cannot drift from the template.

## Start Metro and run

<CommandTabs yarn="start:dev" />

<CommandTabs yarn="android:dev" />

<CommandTabs yarn="ios:dev" />

Use `staging` or `prod` in place of `dev` for the other environments. All three share one Metro server, so one `start` command is enough.

## Env files

| File | Committed | Notes |
| --- | --- | --- |
| `.env.example` | yes | The full list of keys |
| `.env.dev` | yes | Holds no secrets |
| `.env.staging`, `.env.prod` | no | CI writes them from the `ENV_FILE_STAGING` and `ENV_FILE_PROD` secrets |

On iOS, a scheme pre-action copies `.env.<env>` to `.env` before the build. `src/config/env.ts` validates every key with Zod and throws at startup when one is wrong, so a broken build never reaches users:

<AnnotatedCode file="template/src/config/env.ts" highlight="9,30-38,42-46">
  <Note line={4}>Import `ENV`, never `react-native-config`. ESLint enforces it.</Note>
  <Note line={9}>`APP_ENV` is the only key every part of the app can rely on to tell environments apart.</Note>
  <Note line={31}>Cross-field rule: SSL pinning on requires at least two pins, so a pin can be rotated.</Note>
  <Note line={44}>Fail fast with a readable message instead of a broken request later.</Note>
</AnnotatedCode>
