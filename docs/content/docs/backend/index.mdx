An RN-TEMPO app talks to an HTTP API. While the real API does not exist, the app talks to a Tempo local backend: a real HTTP server, with a database, that runs from a folder (`backend/` in the template).

## What you get

| | What it is |
| --- | --- |
| [Local Backend](/docs/backend/local-backend) | A desktop app and a CLI that serve the folder over HTTPS: sign-in, data, file upload, a small CMS and a request log. |
| [Local HTTPS](/docs/backend/local-https) | A certificate for the simulator, the emulator and real devices. |
| [Team server](/docs/backend/team-server) | The same backends on one server, with accounts, roles and API keys. |
| [Test without mock data](/docs/backend/test-without-mocks) | Jest and CI run against the same backend, in memory. |

## One definition

The backend is described by `backend/backend.json`, plus seed data and handler files. You edit it in the app, or in a text editor. The development app, the Jest tests and the CI end-to-end run all read that one folder.

There are no mock files in the template and no mock mode in the app. A test that needs a special answer overrides one route with MSW's `server.use(...)`.

Start with [Local Backend](/docs/backend/local-backend).
