---
title: "ADR-002: Zustand for client state, TanStack Query for server state"
description: "Zustand for client state, TanStack Query for server state"
---

- **Status:** accepted · 2026-10-24

## Context
Most app state is server data (caching, retries, refetch, offline). The rest is small client state (auth status, preferences).

## Decision
- **TanStack Query** owns all server data.
- **Zustand** holds client state, persisted through MMKV where needed.
- Tokens never go in either store; they live in the keychain (C15).
- A docs recipe covers migrating to Redux Toolkit + RTK Query for teams that need it.

## Consequences
- Less boilerplate and a fast ramp-up for new people.
- Two libraries to learn, with a clear rule for which one to use.

## Alternatives
- Redux Toolkit + RTK Query: stronger conventions, but more boilerplate.
